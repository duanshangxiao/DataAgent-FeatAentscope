### 问数核心链路专项整改（最高优先级）

> 背景：当前问数由数据库查询与指标查询两条路径共同承载。统一 `CommonAgent(ReActAgent)` 运行时、动态工具和数据库只读安全校验方向正确，但自动路由、SQL 意图校验门禁、元数据加载效率和指标目录一致性仍依赖 Prompt 或缺少原子边界。
>
> 决策：除 R-04 历史密钥人工轮换需要立即完成外，以下 QRY 专项优先于原架构审查中的其余批次。专项完成前，不以拆分大类、升级框架或增加更多 Agent 类型代替主链路整改。

#### 工程目标与验收原则

| 目标 | 工程约束 | 可验收结果 |
|---|---|---|
| 路由正确 | 用户显式选择优先；自动路由由代码产出可解释决策，不因指标能力已启用就把所有问题送入指标路径 | 强制数据库时指标工具调用数为 0；强制指标时仅在明确失败状态后回退数据库；自动路由场景集有稳定、可重复的期望路径 |
| 结果正确 | 模型负责理解和生成，服务端负责是否允许执行；关键约束不能只写在 Prompt 中 | 任意发送到业务数据库的 SQL 都经过只读、表列权限和本轮问题意图一致性校验；未通过时数据库执行次数为 0 |
| 成本有界 | 正常路径避免重复模型轮次、重复向量召回和重复元数据访问；所有 limit、timeout、迭代次数由服务端设硬上限 | 普通数据库问题不产生指标目录检索；同一轮 datasource 上下文只构建一次；正常指标路径不重复召回同一目录候选 |
| 降级一致 | 指标目录、内存定义和激活状态按同一版本切换；失败保留完整旧版本 | 任意同步批次失败都不会暴露空目录、半目录或“搜索不到但 describe 得到”的混合版本 |
| 歧义可控 | 高风险口径、时间、比较对象和排序条件在执行前澄清；低风险问题不增加无意义交互 | 高风险场景阻断并提出具体问题；明确问题直接执行；用户补充后只保存一次真实问答语义 |
| 可观测、可回归 | 每轮记录路由、工具序列、模型迭代、元数据访问、SQL 门禁、降级原因和耗时，且不记录敏感明文 | 场景验收可自动断言路径与副作用；日志不包含完整 query、arguments、header/body 或凭据 |

#### 目标主链路

```text
用户问题
  → 高风险歧义检查
  → 显式偏好 / 低成本自动路由
  ├─ DB：请求级数据源快照 → 按需 Schema/关系 → SQL 生成与修正
  │      → 服务端 SQL 意图+权限硬门禁 → 有界只读执行 → 回答
  └─ Metric：复用路由候选 → 契约确认 → 有界指标调用
         → SUCCESS 回答 / NEED_CLARIFICATION 澄清 / FALLBACK_TO_DB 显式降级
```
